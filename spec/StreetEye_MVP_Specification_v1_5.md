# StreetEye — Спецификация MVP

> *«Видь город иначе»*

> **Версия:** MVP 1.5 · Апрель 2026  
> **Платформы:** iOS, Android (React Native)  
> **Срок разработки:** 10–12 недель  
> **Команда:** 1 разработчик + дизайнер (part-time)  
> **Цель запуска:** 500 активных пользователей за первый месяц  
> **Языки интерфейса:** Русский (ru), Английский (en) — с возможностью расширения

---

## 1. Философия MVP

Настоящий документ описывает минимально жизнеспособный продукт — не уменьшенную версию большого продукта, а самодостаточный продукт, решающий одну задачу хорошо: дать фотографу задание и помочь его выполнить.

**Принцип отбора функций для MVP:**

- Убирается всё, что не нужно для первого выполненного задания
- Убирается всё, что требует более 2 недель разработки
- Убирается всё, что нельзя проверить на 100 пользователях

### Что мы НЕ делаем в MVP

Явный список исключений защищает от расползания scope:

| Не делаем | Почему |
|---|---|
| AI-анализ фотографий | Отдельный продукт, высокий риск, дорого |
| Геолокационные задания | Сложная инфраструктура, не критично для ценности |
| Heat Mode (задание каждые 15 мин) | Нет доказательств спроса на старте |
| Интеграция с Apple Watch | Вторичная функция, малая аудитория |
| Публичная лента / соцсеть | Противоречит ценности приватности |
| Экспорт статистики | Нет данных для экспорта без истории |
| Masterclass-курсы | Требует партнёрств, не MVP |
| Онлайн-хранение фото | Дорогостоящая инфраструктура, приватность |

## 2. Ядро продукта

MVP состоит из трёх связанных модулей. Всё остальное — следующие итерации.

| Модуль 1 | Модуль 2 | Модуль 3 |
|---|---|---|
| **Рандомайзер заданий** — получить задание быстро, без лишних шагов | **Онбординг** — настроить уровень и предпочтения за 60 секунд | **Приватный дневник** — зафиксировать результат и вернуться к нему |

## 3. Онбординг

Онбординг — первое взаимодействие с продуктом. Если он неудобен, пользователь не вернётся. Цель: от установки до первого задания — не более 90 секунд.

### 3.1 Экраны онбординга

| # | Экран | Действие пользователя | Результат |
|---|---|---|---|
| 1 | Приветствие | Нажимает «Начать» | Переход к выбору языка |
| 2 | Язык | Выбирает: Русский / English. По умолчанию — язык устройства | `locale` сохраняется в AsyncStorage, интерфейс переключается мгновенно |
| 3 | Уровень | Выбирает: Новичок / Средний / Профи | Сохраняется локально в AsyncStorage |
| 4 | Предпочтения | Выбирает 1–2 категории (Визуальное / Техническое / Социальное / Ограничения) | Сохраняется локально в AsyncStorage |
| 5 | Уведомления | Разрешает или пропускает | Push-напоминания настроены |
| 6 | Первое задание | Видит задание, нажимает «Пошёл снимать» | Переход на главный экран |

**Гостевой режим и данные онбординга:**

Онбординг проходит до регистрации. Все данные (язык, уровень, категории) хранятся локально в AsyncStorage. На экране 6 первое задание загружается через публичный гостевой эндпоинт (`GET /tasks/random/guest`) с передачей параметров из AsyncStorage. Задание и его `taskId` сохраняются локально.

При нажатии «Пошёл снимать» — гость переходит на главный экран и видит задание. Серверная сессия не создаётся (гость не авторизован). Когда гость нажимает «Задание выполнено» — появляется предложение зарегистрироваться.

**Флоу перехода гость → зарегистрированный пользователь:**

1. Гость нажимает «Задание выполнено» → bottom sheet с предложением зарегистрироваться
2. Пользователь регистрируется → `POST /auth/register` с данными онбординга (level, categories, locale)
3. Сразу после регистрации клиент автоматически создаёт серверную сессию (`POST /sessions` с `taskId` из AsyncStorage)
4. Затем клиент завершает сессию (`PATCH /sessions/:id` с `status: COMPLETED`)
5. Открывается bottom sheet записи в дневник — пользователь видит привычный флоу завершения задания

Весь процесс прозрачен для пользователя — между нажатием «Задание выполнено» и формой дневника он только вводит email и пароль.

**Правило онбординга:** не требовать регистрацию до первого выполненного задания. Email/аккаунт запрашиваем только при попытке сохранить прогресс.

## 4. Рандомайзер заданий

### 4.1 База контента MVP

30 заданий в базе MVP — достаточно для первых 2–3 месяцев без повторений при ежедневном использовании. Каждое задание — полноценная карточка.

| Категория | Новичок | Средний | Профи |
|---|---|---|---|
| Визуальное | 3 задания | 3 задания | 2 задания |
| Техническое | 3 задания | 3 задания | 2 задания |
| Социальное | 3 задания | 2 задания | 2 задания |
| Ограничения | 2 задания | 3 задания | 2 задания |
| **Итого** | **11** | **11** | **8 → 30** |

### 4.2 Структура карточки задания

| Поле | Описание |
|---|---|
| Название | Короткое, запоминающееся. Пример: «Только тени» |
| Категория | Визуальное / Техническое / Социальное / Ограничение |
| Уровень | Новичок / Средний / Профи |
| Описание | 2–3 предложения: что снимать, на что обращать внимание |
| Совет | 1 практическая подсказка по технике или подходу |
| Ограничение по времени | Рекомендация: 30 / 60 / 90 минут |
| Теги | Для фильтрации: `#свет` `#ч/б` `#люди` `#геометрия` |

### 4.3 Логика выборки

- По умолчанию — случайное задание из уровня и категорий пользователя
- Не повторять последние 5 заданий
- Кнопка «Другое задание» — переключает без сохранения (Free: 1 раз за сессию, Premium: 3 раза за сессию)
- Кнопка «Взять это» — фиксирует задание как активное, создаёт сессию на сервере

### 4.4 Главный экран во время задания

- Название и описание задания — крупно
- Таймер (опциональный, включается пользователем)
- Совет — свайп вниз
- Кнопка «Задание выполнено»
- Кнопка «Сохранить на потом» — откладывает задание

## 5. Приватный дневник

Дневник — инструмент рефлексии, не галерея. Хранится локально на устройстве. Никакие фотографии не покидают телефон без явного действия пользователя.

### 5.1 Запись в дневнике

| Поле | Описание |
|---|---|
| Задание | Автоматически: название и категория |
| Дата выполнения | Автоматически |
| Прикреплённое фото | Опционально, выбирается из галереи, хранится локально |
| Заметка | Свободный текст: «Что получилось / что нет», макс. 500 символов |
| Самооценка | 3 варианта: Не получилось / Частично / Получилось |
| Статус | Выполнено / Пропущено |

### 5.2 Список записей

- Хронологический список всех записей
- Фильтр по категории и уровню
- Краткая статистика вверху: «Выполнено заданий: 12, Серия: 3 дня подряд»
- Нет аналитики, нет графиков — только список и счётчик

### 5.3 Бейджи (минимальный набор)

4 бейджа для MVP — достаточно для ощущения прогресса без перегрузки:

| Бейдж | Условие | Иконка |
|---|---|---|
| Первый шаг | Выполнить первое задание | 🏁 |
| Неделя | 7 заданий за любой период | 🗓 |
| Серия x3 | 3 дня подряд | 🔥 |
| Всё попробовал | По одному заданию в каждой категории | ⭐ |

## 6. Монетизация MVP

> **🚫 MVP Launch Policy (v1.5): монетизация отключена при запуске**
>
> Код монетизации (SubscriptionsModule, PromoModule, paywall, IAP, лимиты Free/Premium) **реализован и присутствует в кодовой базе**, но **деактивирован** на период первичного запуска MVP.
>
> **Причина:** сбор данных об удержании и паттернах использования до введения ограничений. Монетизация возвращается в **v1.1** после достижения Retention Day 7 ≥ 25%.
>
> **Что это означает на практике:**
> - Все пользователи получают полный доступ (эквивалент Premium) без оплаты
> - Paywall не показывается, лимиты Free не применяются
> - Промокоды не предлагаются (модуль присутствует, но точки входа скрыты в UI)
> - Кнопка «Управление подпиской» и «Активировать промокод» в профиле скрыты
>
> **Как вернуть монетизацию (чеклист для v1.1):**
> 1. Бэкенд: убрать флаг `MONETIZATION_ENABLED=false` из env → все ограничения включатся автоматически
> 2. Мобильное: раскомментировать проверки `isPremium` в store и компонентах (помечены `// [MONETIZATION]`)
> 3. Мобильное: вернуть `paywall.tsx` в навигацию и точки входа из профиля
> 4. Тест: пройти флоу достижения лимита → появление paywall → покупка → снятие лимита

В MVP монетизация минимальна. Цель — не заработать, а проверить готовность платить. Paywall появляется органично, не раздражает.

| | Free | Premium ($3.99/мес или промокод) |
|---|---|---|
| Задания | 10 заданий в месяц (не навсегда) | Все 30+ заданий |
| Дневник | Последние 10 записей | Полная история |
| Бейджи | 2 из 4 | Все бейджи |
| «Другое задание» | 1 раз за сессию | 3 раза за сессию |
| Пробный период | — | 7 дней бесплатно |

**Способы получения Premium:**

- Подписка $3.99/мес через App Store / Google Play (автопродление)
- Промокод — одноразовый код, даёт lifetime Premium. Используется для маркетинга, блогеров, компенсаций

**Принципы paywall:**

- Paywall показывается только при достижении лимита, не раньше
- На paywall доступна ссылка «Есть промокод?» — альтернативный путь активации Premium
- Не блокировать приложение — всегда есть что сделать на Free
- A/B тест цены: $2.99 vs $3.99 vs $4.99 с первой недели

## 7. Технический стек MVP

Принцип: минимальный стек, который можно поддерживать одному разработчику и который не упадёт при нагрузке до 10 000 пользователей.

| Компонент | Технология | Обоснование |
|---|---|---|
| Мобильное приложение | React Native + Expo | Один код для iOS/Android, быстрый старт |
| Бэкенд | NestJS (монолит) | Без микросервисов до 50K пользователей |
| База данных | PostgreSQL (один инстанс) | Надёжно, ACID, легко мигрировать |
| Кэш | Redis (опционально) | Подключить если появятся медленные запросы |
| Локальное хранение | AsyncStorage / SQLite | Фото и дневник — только на устройстве |
| Авторизация | Passport.js (Local Strategy) + JWT | Email + пароль, bcrypt для хэширования, access + refresh токены в PostgreSQL, без сторонних OAuth-зависимостей |
| Push-уведомления | Expo Notifications | Встроено в Expo, не нужен отдельный сервис |
| Email-сервис | Resend (free tier) | 3 000 писем/месяц бесплатно — хватит на весь период MVP |
| Безопасность | @nestjs/throttler + helmet + bcrypt | Rate limiting, HTTP-заголовки безопасности, хэширование паролей — всё встроено в NestJS, бесплатно |
| Аналитика | Umami (self-hosted, open source) | Бесплатно, open source, разворачивается на своём сервере рядом с бэкендом |
| Деплой | VPS (Hetzner / DigitalOcean) + Docker Compose | От ~$5/мес, полный контроль, GitHub Actions для CI/CD |
| Контент (задания) | JSON-файлы на ru и en как seed-источник для PostgreSQL | Нет нужды в CMS для 30 заданий. JSON — исходник, задания загружаются в БД через seed-скрипт |
| Локализация (i18n) | i18next + react-i18next | ru + en на старте. Определение языка по системным настройкам устройства с ручным переключением |

**Что намеренно убрано из стека:**

- Kafka / RabbitMQ — нет распределённых процессов
- Kubernetes — не нужен до 100K пользователей
- Отдельный Python-сервис для AI — нет AI в MVP
- S3 / MinIO — фото хранится локально
- Сторонние OAuth-провайдеры (Google, Apple, Supabase, Auth0) — авторизация через Email/Password, полностью самостоятельная реализация

### 7.2 Защита от фрода и атак

Все меры реализуются встроенными инструментами NestJS — без платных сервисов и внешних зависимостей.

**Email-флоу авторизации:**

- Подтверждение email при регистрации — аккаунт неактивен до перехода по ссылке. Блокирует массовую регистрацию ботами
- Ссылка сброса пароля — одноразовая, TTL 30 минут, хранится в PostgreSQL как хэш
- Resend отправляет не более 3 000 писем/месяц бесплатно — достаточно для 500 пользователей MVP с запасом

**Защита эндпоинтов:**

- Rate limiting (`@nestjs/throttler`) — не более 5 попыток входа с одного IP за 15 минут, затем временная блокировка. Защита от брутфорса
- `helmet` — выставляет защитные HTTP-заголовки (CSP, HSTS, X-Frame-Options). Подключается одной строкой
- CORS — ограничен только мобильным клиентом приложения, посторонние домены заблокированы
- SQL-инъекции — закрыты автоматически параметризованными запросами TypeORM/Prisma

**Управление токенами:**

- Access token — короткий TTL (15 минут), хранится в памяти приложения, не доступен из JS
- Refresh token — TTL 30 дней, хранится в PostgreSQL как bcrypt-хэш, инвалидируется при выходе или смене пароля
- bcrypt (cost factor 12) — хэширование паролей, защита от утечки базы данных

## 8. Мультиязычность (i18n)

На старте поддерживаются два языка: русский (ru) и английский (en). Архитектура i18n проектируется так, чтобы добавление нового языка требовало только создания нового файла переводов без изменения кода.

### 8.1 Стек локализации

- **Мобильное приложение:** i18next + react-i18next. Стандарт для React Native, поддерживает lazy loading переводов и pluralization
- **Бэкенд:** задания и контент хранятся в БД с полями `title_ru` / `title_en`, `description_ru` / `description_en`, `tip_ru` / `tip_en`. Бэкенд возвращает нужную локаль по заголовку `Accept-Language`
- **Email-письма:** шаблоны Resend в двух вариантах (ru / en). Язык письма — по `locale` пользователя в БД

### 8.2 Определение и хранение языка

- При первом запуске — язык определяется по системным настройкам устройства (`expo-localization`). Если язык устройства не поддерживается — по умолчанию английский
- На экране 2 онбординга пользователь может явно выбрать язык — выбор сохраняется в AsyncStorage и в профиле пользователя на бэкенде (поле `locale`)
- Смена языка доступна в настройках профиля в любой момент без перезапуска приложения

### 8.3 Что локализуется

| Элемент | В MVP | Реализация |
|---|---|---|
| Интерфейс приложения (кнопки, подписи, сообщения) | ✅ Да | JSON-файлы переводов: `locales/ru.json` и `locales/en.json` |
| Контент заданий (название, описание, совет) | ✅ Да | Поля `_ru` / `_en` в БД. Бэкенд отдаёт по `Accept-Language` |
| Email-письма (confirm, reset, welcome) | ✅ Да | Два шаблона Resend на каждое письмо. Язык — по полю `locale` пользователя |
| Push-уведомления | ✅ Да | Текст уведомления формируется на бэкенде по `locale` пользователя |
| Сообщения об ошибках от бэкенда | ❌ Нет | Коды ошибок машино-читаемые (`INVALID_CREDENTIALS` и т.д.). Перевод — на клиенте по коду. v1.1 |

|---|---|---|
| Контент (30 заданий) затянется | 🔴 Высокий | Шаблон задания заполняется параллельно с разработкой, с недели 1. Не ждать конца разработки |
| Низкий retention — продукт не цепляет | 🟡 Средний | Мягкие напоминания (не спам), функция «Отложить задание», проверка онбординга через 50 пользователей |
| 30 заданий мало — пользователь всё увидит | 🟡 Средний | На неделе 6 проверить метрику «повтор задания». Если >20% видят повтор — добавить 20 заданий до запуска |
| Сложность публикации в App Store | 🟢 Низкий | Зарегистрировать Apple Developer аккаунт на неделе 1. Отправить TestFlight-версию на неделе 8 |

## 12. После MVP: дорожная карта

Функции, не попавшие в MVP, не потеряны — они ждут подтверждения спроса.

| Итерация | Когда | Что добавляем |
|---|---|---|
| v1.1 | Месяц 3–4 | **Включение монетизации** (лимиты Free, paywall, IAP, промокоды), 7-Day Challenge, Heat Mode, фильтры по тегам |
| v1.2 | Месяц 4–5 | Автоматический коллаж марафона, экспорт дневника |
| v1.3 | Месяц 5–6 | Геолокационные задания (Location Based mode) |
| v2.0 | Месяц 6+ | AI-анализ фото (если retention > 30% и MAU > 5 000) |
| v2.x | Месяц 8+ | Watch Integration, Masterclass-курсы, веб-версия |

**Правило запуска следующей итерации:** не начинать v1.1 пока Retention Day 7 не превысит 25%. Рост функциональности без удержания — бесполезен.

## Заключение

Этот MVP — ответ на один вопрос: «Будут ли люди регулярно возвращаться в приложение, чтобы получить задание для уличной съёмки?»

Если ответ «да» — у StreetEye есть будущее и основание для всех функций из полной спецификации. Если ответ «нет» — мы узнаем это через 4 недели после запуска, не через 6 месяцев разработки.

| Полная спецификация v1.0 | MVP v1.0 (этот документ) |
|---|---|
| Микросервисы + Kubernetes | NestJS монолит + VPS + Docker Compose |
| 100+ заданий | 30 заданий |
| 5 марафонов | 0 марафонов (v1.1) |
| AI-анализ | Самооценка пользователя |
| 6 недель (нереально) | 10 недель (реалистично) |
| Неизвестный результат | Проверяемая гипотеза |
